# گزارش مرحلهٔ ۵: بازنویسی هسته، کالیبراسیون و NNUE خودآموز

همهٔ اعداد زیر روی یک ماشین ابری ۴ هسته‌ای (Xeon 2.1GHz، AVX-512) اندازه‌گیری شده‌اند. فایل‌های خام در `benchmarks/v5-calibration` و `benchmarks/v5-nnue` قرار دارند.

## ۱. ارزیابی معماری قبلی

- ارزیاب فقط ارزش مهره‌ها را حساب می‌کرد.
- در هر گره `board.status()` فراخوانی می‌شد، یعنی تولید کامل حرکت‌های قانونی.
- جدول انتقال فقط وقتی شمارندهٔ نیم‌حرکت صفر بود خوانده یا نوشته می‌شد. بنابراین در بیشتر گره‌ها عملاً بی‌اثر بود.
- history فقط درون یک جست‌وجو معنا داشت. هرس‌ها محدود بودند و NNUE (Caissa) وزن قانونی و کارآمد نداشت.

نتیجه: موتور در برابر هستهٔ جدید **۸۰ از ۸۰** باخت.

## ۲. معماری جدید

| بخش | پیاده‌سازی |
|---|---|
| صفحه | بیت‌برد، magic bitboard ساخته‌شده در build.rs، copy-make، کلیدهای Zobrist / پیاده / غیرپیاده |
| تولید حرکت | شبه‌قانونی با ماسک pin و کیش؛ perft روی ۶ موقعیت مرجع درست است |
| ترتیب حرکت | مراحل: حرکت TT، captureهای خوب (SEE + capture history)، killer، counter، quietها (butterfly + continuation 1/2/4)، captureهای بد |
| جست‌وجو | PVS، aspiration، RFP، razoring، null move با verification، ProbCut، IIR، LMP، futility، SEE pruning، history pruning، singular / double / negative extension، LMR جدولی، correction history پیاده و غیرپیاده، mate distance pruning |
| TT | بدون قفل، ۴ ورودی در هر خط cache، XOR-validated، مشترک بین نخ‌ها |
| موازی | Lazy SMP |
| ارزیاب | NNUE خودآموز (768→256)×2→1 با SCReLU و ۸ bucket خروجی؛ ارزیاب کلاسیک tapered به‌عنوان پشتیبان |
| زمان | حد نرم و سخت، با مقیاس بر اساس پایداری بهترین حرکت و سهم گره‌ها |

## ۳. کالیبراسیون رتبه

**روش.** گانتلت در برابر استاک‌فیش ۱۷.۱ با `UCI_LimitStrength` در سطح‌های ۱۳۲۰ تا ۳۱۹۰. کنترل زمان 10+0.1، دو بازی برای هر گشایش، و کتاب گشایش خودساخته (۲۸۵۷ موقعیت متوازن). رتبه‌ها با Bradley-Terry و لنگرهای ثابت برآورد شده‌اند و بازهٔ اطمینان از bootstrap روی جفت‌ها آمده است (`tools/rating.py`).

| موتور | برآورد | ۹۵٪ | بازی |
|---|---|---|---|
| main قدیمی `65ec72a` | ۱۶۷۷ | [۱۵۹۲, ۱۷۵۲] | ۱۲۰ |
| هستهٔ جدید (کلاسیک) | ۲۹۹۱ | [۲۹۳۴, ۳۰۴۳] | ۱۶۲ |

**محدودیت‌ها:**
- `UCI_Elo` استاک‌فیش در 60s+0.6s نسبت به CCRL 40/4 کالیبره شده است. در 10+0.1 مقیاسش ممکن است جابه‌جا شود (مثلاً سطح‌های ۳۰۰۰ و ۳۱۹۰ با هم سازگاری کامل نداشتند).
- این رتبه **برآورد محلی** است، نه رتبهٔ رسمی CCRL.
- سقف این نردبان ۳۱۹۰ است. برای نسخه‌های قوی‌تر باید لنگرهای دیگری اضافه شوند: موتورهای مستقل با رتبهٔ منتشرشده، یا استاک‌فیش کامل با بودجهٔ گره محدود.
- فاصلهٔ تقریبی با قوی‌ترین موتورها روی سخت‌افزار یکسان: استاک‌فیش ۱۷ در فهرست‌ها حدود ۳۶۰۰ تا ۳۷۰۰ است. پس فاصلهٔ فعلی حدود ۶۰۰ Elo یا بیشتر است.

## ۴. NNUE

مسیر انتخاب‌شده: آموزش روی داده‌های self-play خود فرزین با trainer خود فرزین. بنابراین وزن‌ها مال پروژه‌اند و مشکل مجوز ندارند. از وزن‌ها و ارزیابی‌های استاک‌فیش یا Reckless استفاده نشده است.

| آزمایش (در برابر ارزیاب کلاسیک) | نتیجه |
|---|---|
| ۲٫۵M موقعیت، wdl 0.3، کنترل زمان | −۶۳ [−۱۲۹, −۱] |
| ۵M، wdl 0.3، کنترل زمان | −۲۰۴ (۵۴ جفت) |
| ۵M، wdl 0.6، fixed 20k nodes | −۲۷۷ |
| ۵M، wdl 0.3، fixed nodes | −۱۵۲ |
| ۵M، hidden 128، fixed nodes | −۴۸ |
| ۵M، scale 160، wdl 0.0 / 0.2 / 0.4 | +۴۲ / −۱۳ / −۵۵ |
| **۵M، wdl 0.0، scale 400، fixed nodes** | **+۹۱ [+۴۵, +۱۴۱]** |
| **همان شبکه، 10+0.1، ۱۴۸ جفت** | **+۵۰٫۸ [+۱۶٫۸, +۸۵٫۹]** ← پیش‌فرض فعلی |

**درس‌ها:**
- با این حجم داده و self-play کوتاه، نتیجهٔ بازی (WDL) برچسب پرنویزی است و به‌شدت ضرر می‌زند.
- مقیاس sigmoid برازش‌شده روی داده حدود ۱۶۰cp است.
- بررسی شد که overflow در لایهٔ خروجی رخ نمی‌دهد (`examples/net_overflow.rs`).
- سرعت NNUE-256 با SIMD خودکار کامپایلر تقریباً هم‌اندازهٔ ارزیاب کلاسیک است (حدود ۱٫۲ تا ۱٫۵M nps روی یک هسته).

## ۵. گلوگاه‌ها و مسیر بعدی

۱. **داده.** سرعت فعلی حدود ۱۴۰ موقعیت در ثانیه برای هر هسته است. شبکهٔ ۲۵۶ احتمالاً با ۵۰ تا ۱۰۰ میلیون موقعیت به سقفش می‌رسد. شبکه‌های رقابتی میلیاردها موقعیت می‌خواهند.

۲. **نسل‌های بعدی NNUE:** datagen با شبکهٔ قبلی، آموزش روی همهٔ نسل‌ها، و آزمون wdl کوچک (۰٫۱) وقتی کیفیت بازی‌ها بالا رفت.

۳. **معماری شبکه:** king bucket (مثلاً HalfKA با ۸ تا ۱۶ bucket)، لایهٔ پنهان ۵۱۲ تا ۱۵۳۶، و مقیاس‌بندی خروجی. همهٔ این‌ها دادهٔ بیشتری می‌خواهند.

۴. **سرعت:** SIMD دستی (AVX2 / AVX-512) برای accumulator و لایهٔ خروجی، به‌روزرسانی lazy، و prefetch بهتر.

۵. **تنظیم پارامترهای جست‌وجو برای مقیاس NNUE** با `tools/spsa.py`. حاشیه‌های فعلی برای ارزیاب کلاسیک انتخاب شده‌اند.

۶. **کالیبراسیون در 60+0.6** با لنگرهای بالای ۳۱۹۰.

## ۶. راهنمای اجرا روی سرور

**پیش‌نیاز:** Rust stable، Python 3 و `pip install chess`. برای کالیبراسیون، باینری رسمی استاک‌فیش لازم است (مثلاً `stockfish-ubuntu-x86-64-avx2` از صفحهٔ releases).

```sh
git clone https://github.com/ar-karkon/farzin && cd farzin
cargo build --release
./target/release/farzin bench 12            # بررسی سلامت

# یک نسل کامل: داده -> آموزش -> غربال -> SPRT
WORK=/data/farzin tools/pipeline.sh 2 20000000 $(nproc)
```

`pipeline.sh` نسل جدید را با شبکهٔ فعلی (`nets/default.nnue`) تولید می‌کند، روی همهٔ نسل‌های `WORK/data` آموزش می‌دهد، و شبکهٔ جدید را در برابر شبکهٔ قبلی می‌سنجد: اول غربال fixed-nodes، سپس SPRT [0, 5]. اگر SPRT H1 را پذیرفت، شبکه را در `nets/default.nnue` کپی و در `nets/README.md` ثبت کنید.

**برآورد زمان روی سرور ۶۴ هسته‌ای:**
- ۲۰ میلیون موقعیت در حدود ۴۵ دقیقه
- آموزش شبکهٔ ۲۵۶ روی ۵۰M موقعیت در کمتر از ۱۰ دقیقه
- SPRT در 10+0.1 حدود ۱۰۰۰ بازی در هر ۲۰ دقیقه

**کالیبراسیون دوره‌ای:**

```sh
SF=/path/stockfish
python3 tools/arena.py --gauntlet --engine name=farzin,cmd=target/release/farzin \
  --engine name=sf2800,cmd=$SF,opt.UCI_LimitStrength=true,opt.UCI_Elo=2800 \
  --engine name=sf3000,cmd=$SF,opt.UCI_LimitStrength=true,opt.UCI_Elo=3000 \
  --engine name=sf3190,cmd=$SF,opt.UCI_LimitStrength=true,opt.UCI_Elo=3190 \
  --tc 60+0.6 --pairs 100 --concurrency $(nproc) --out calib.json
python3 tools/rating.py calib.json --anchor sf2800=2800 --anchor sf3000=3000 --anchor sf3190=3190
```

**اگر GPU دارید:** trainer فعلی روی CPU است. برای شبکه‌های بزرگ‌تر از ۵۱۲، trainer را به GPU ببرید یا از یک trainer متن‌باز با مجوز سازگار (مثلاً bullet، MIT) استفاده کنید. فرمت داده و شبکه (`FZN1`) در `src/datagen.rs` و `src/net.rs` مستند شده است.
